## A1

¿Qué es un requisito de software y cuáles son sus principales tipos? Explícamelo con un ejemplo sencillo.

Estado: critic_finished_unverified

Un requisito de software es una característica o funcionalidad específica que el sistema debe poseer o realizar para satisfacer las necesidades de los usuarios y cumplir con los objetivos de negocio. Estos requisitos pueden clasificarse en varios tipos:

1. **Requisitos funcionales**: describen lo que el sistema debe hacer. Por ejemplo, si estamos desarrollando una aplicación bancaria, un requisito funcional podría ser "La aplicación debe permitir a los usuarios consultar su saldo actual". Estos requisitos se dividen en:
   - **Requisitos de información**: describen la información que el sistema debe almacenar y gestionar. Por ejemplo, "La aplicación debe almacenar el nombre completo, número de cuenta y saldo de cada usuario".
   - **Reglas de negocio**: describen las reglas o restricciones que el sistema debe cumplir. Por ejemplo, "La aplicación debe rechazar cualquier transacción que supere el límite diario establecido por el usuario".
   - **Requisitos de conducta**: describen capacidades transversales o interacciones sencillas con el usuario. Por ejemplo, "La aplicación debe mostrar un mensaje de bienvenida cuando el usuario inicia sesión".

2. **Requisitos no funcionales**: describen las características de calidad del sistema, como su rendimiento, seguridad, usabilidad, entre otros. Por ejemplo, "La aplicación debe responder a las solicitudes de consulta de saldo en menos de dos segundos".

3. **Requisitos de integración**: describen con qué servicios debe integrarse el sistema. Por ejemplo, "La aplicación debe estar conectada a un servicio de autenticación externo para verificar la identidad del usuario".

4. **Requisitos de dominio**: describen restricciones tecnológicas que el sistema debe cumplir. Por ejemplo, "La aplicación debe ser compatible con navegadores web modernos como Chrome, Firefox y Edge".

Estos requisitos son fundamentales para asegurar que el sistema cumpla con las expectativas de los usuarios y los objetivos de negocio. Por ejemplo, si se está desarrollando una aplicación de gestión de inventarios, un requisito funcional podría ser "La aplicación debe permitir a los usuarios agregar nuevos productos al inventario", mientras que un requisito no funcional podría ser "La aplicación debe mantenerse estable incluso cuando se realicen múltiples operaciones simultáneamente".

## A2

No he entendido bien la diferencia entre un requisito funcional y uno no funcional. ¿Puedes explicármela de otra manera?

Estado: critic_finished_unverified

Un requisito funcional y uno no funcional tienen diferentes focos en la especificación de lo que debe hacer un sistema de software.

**Requisito funcional:** Este tipo de requisito se centra en lo que el sistema debe hacer. Específicamente, describe las acciones que el sistema debe realizar para cumplir con las necesidades de los usuarios. Por ejemplo, si estás trabajando en una aplicación de gestión de inventarios, un requisito funcional podría ser "La aplicación debe permitir a los usuarios agregar nuevos productos al inventario". Este requisito indica una acción específica que el sistema debe poder realizar.

**Requisito no funcional:** En contraste, un requisito no funcional se enfoca en las características de calidad del sistema, como su rendimiento, seguridad, usabilidad, entre otros. Estos requisitos no describen directamente lo que el sistema debe hacer, sino cómo debe hacerlo o cómo debe comportarse. Por ejemplo, un requisito no funcional para la misma aplicación de gestión de inventarios podría ser "La aplicación debe responder a las solicitudes de consulta de saldo en menos de dos segundos". Este requisito se refiere a la velocidad de respuesta del sistema, que es una característica de calidad.

En resumen, los requisitos funcionales se centran en las acciones específicas que el sistema debe realizar, mientras que los requisitos no funcionales se centran en las características de calidad del sistema. Ambos son importantes para garantizar que el sistema cumpla con las necesidades de los usuarios y los objetivos de negocio.
