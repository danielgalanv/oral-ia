# Opt-in scope classifier v2

Separate entry point: `scope_classifier_v2.classify_scope_v2`; no default or v1 caller changes. Output model has `primary_intent`, included/excluded block IDs, optional mixed spans, optional supporting mention span and optional shown-history index. Fields `status`, `standalone`, teacher approval and publication authority are forbidden in model output. The host derives status and standalone mechanically from primary intent before reusing v1 literal span/policy checks. This prevents a second contradictory label; it does not prove correct interpretation of the primary intent.

An auxiliary interpretation requires an included block anchor and an exact current-input witness for the supporting mention. No independent excluded block is accepted on that route. The anchor-to-mention relation still needs semantic evaluation. Mixed requests retain two literal, disjoint question spans; only the included span becomes the RAG question. Hidden/oversized history, foreign/missing block IDs, guessed spans and missing referents fail closed. The original v1 S02 remains rejected; v2 never rewrites a saved v1 output.

Input descriptions are a separate opt-in dependency, `BlockMetadata`. They cover the entire policy inventory, including prerequisites, with a versioned metadata hash, policy hash, category/JSON pointer, teacher presentation filename/hash/page and literal heading quote. Missing/duplicate/foreign blocks, changed bytes, changed policy, wrong source filename/hash or quote, and unknown metadata versions reject the request. Revalidate policy and metadata before dispatch and after the outcome. Receipts must retain the full request, metadata digest and version, model identity and effective chat template. The caller pins the metadata digest before inference; a self-declared hash in provider output has no authority.

The current descriptions are technical paraphrases of scope headings and the approved activity boundary. They are not substitute academic passages, teacher approval of answers, or a claim to exhaustive definitions of each subject. They add no question-specific vocabulary for S01; all 21 policy entries receive the same provenance treatment. The presentation's extra-content list does not override the approved inclusion of agile development. Page 8 records the included schedule, page 7 lists extra blocks, page 5 defines prerequisites and the programming-course boundary. Policy approval determines current scope when headings overlap.

One call, 256 tokens, 30000 ms, existing local port, no retries or fallbacks. `unknown`, contract errors and stale metadata produce no RAG query or participant output. V2 does not evaluate answer truth, sufficiency or coverage. G2, SC001, consent, access, T090/T150, reserve and participant routes remain unchanged.

Combined evaluation of v2 and descriptions is a product trial, not causal attribution to either change. The old twenty-case trial remains exposed regression and its remaining call budget is not reused.
