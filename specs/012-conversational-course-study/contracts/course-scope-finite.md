# Finite course scope — explicit lab option v1

Entry point: `scope_finite.classify_finite_scope(text, shown_history, provider=..., binding=..., db=..., metadata=..., receipt_sink=...)`. It returns a structured `FiniteScopeResult`; it is not registered in participant routes or substituted into v1/v2. An existing cached local provider can execute it. No teaching answer is emitted.

The compiler reads all included/excluded standalone block IDs from the current bound policy. It enumerates two controls, N included targets, N auxiliary anchors, M standalone exclusions and N×M mixed pairs: `2 + 2N + M + NM`. Current policy yields 120. It rejects duplicate/overlapping/invalid IDs, more than 256 alternatives or any alternative longer than 512 characters, with an explicit diagnostic. It never drops blocks to fit a backend limit. Prerequisites remain in the descriptions and boundary policy; they do not become standalone included blocks.

Each target is an explicit finite JSON object carrying only applicable fields. The target and optional reference steps must have `finite_decoder=true` in the raw local worker receipt, a consistent enabled flag in the outcome, identical raw/outcome text and membership in the exact compiled alternatives. Missing/false flags or a format-instruction fallback raise `FiniteScopeError`, carrying receipts. Backend syntax capability is distinct from correct semantic selection or source authorization.

Context is conditional. The existing context planner determines whether the input needs a shown referent; only then is a finite selection among none/actual indices requested. None gives uncertainty. Otherwise history is not exposed to target selection. This planner trigger remains a fallible part of conversational coverage; it does not demonstrate understanding of every natural-language ellipsis. After a reference is selected, target sees only that shown row. Historical academic prose is not evidence. An included followup can use the registered included-block title as a retrieval hint; raw historical clauses are never appended to the resulting RAG query.

A straightforward included/excluded/control decision needs one target call and no literal or reference call. Auxiliary targets require one open exact-text witness. Mixed targets require two open exact-text witnesses. The host finds positions via a unique exact match, with no stripping, case folding, normalization or rewriting. Empty, missing, repeated or overlapping witnesses produce `uncertain_scope`, `rag_question=None`. No occurrence is picked arbitrarily. Mixed output uses only the allowed literal portion and `rag_history=()`; excluded clauses cannot return through this output's history. Caller integration must consume these sanitized fields, not rebuild a query from the original mixed turn. The host derives final status and standalone fields from the finite variant.

Literal extraction is **not** token-restricted and its semantic pertinence is **not** automatically verified. A uniquely occurring but semantically wrong substring is still possible and needs the evaluation oracle. These checks are not the academic answer verifier. Result flags remain `literal_decoder_constrained=false`, `semantic_verification=unverified`, `publication_allowed=false`.

One shared monotonic 30-second budget, at most four calls, reserving no more than 512 generation tokens: reference 32, target 128, and up to two literals of 176 each. A call uses only remaining wall time and cannot begin with less than 1000 ms. No retry or repair. Exhaustion/incomplete generation gives uncertainty; cancellation propagates to the owned adapter. Current policy and pinned metadata are revalidated around each call and before returning. Deadline expiry during final checks also downgrades to uncertainty. Synchronous local reads are checked after completion rather than claimed to have hard real-time cancellation.

Each actual step records request/schema, raw outcome, worker exchange, elapsed start/end and rejection/error; the sink can persist the receipt before/after the call, including failures. No records are fabricated for unexecuted calls. A provider protocol error blocks rather than converting a false decoder flag into an accepted decision. Consent, access, T090/T150, G2, SC001 and the reserve are unchanged.

Tokenizer evidence uses the real Qwen2Tokenizer of the installed worker runtime with CUDA disabled and local files only. It checks token roundtrip, all legal prefix transitions, full-sequence EOS and foreign-prefix rejection for all actual policy alternatives; no model weights or inference. It proves the finite protocol is mechanically representable by this tokenizer, not that a model chooses correctly.
